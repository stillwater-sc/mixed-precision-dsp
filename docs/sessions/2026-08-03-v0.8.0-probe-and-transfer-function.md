## Design decisions worth remembering

- **Two independent paths to the same answer.** `sweep_bode` measures the
  realized filter; `pole_zero` derives the ideal prototype. Having both is what
  makes the module useful for a mixed-precision library — the gap between them
  *is* the quantization error, and it is now directly observable.
- **Zero-cost instrumentation.** `NoOpProbe` means probing is a template
  parameter, not a runtime branch, which keeps it usable in the inner loop.
- **Shared elliptic math.** `elliptic_sn_series` now has one implementation
  serving both filter design and pole/zero analysis. If it had been copied, the
  two would have drifted.
